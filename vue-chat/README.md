# אימות נתונים בצ'אט - גרסת Vue

המשימה "אימות נתונים" מאתר מתגייסים. היא מחליפה את הטופס של תחנת אימות
הנתונים בשיחה עם העוזר החכם. העוזר מציג למלש"ב מה רשום עליו במערכת, מבקש
לאשר או לתקן, משלים יחד איתו את מה שחסר, ובסוף המלש"ב חותם.

זו המרה אחד-לאחד של המוקאפ ב-React (`src/app/components/DataVerificationChatPage.tsx`
בתיקייה מעל), עם אותו עיצוב, אותו תסריט ואותה התנהגות.

## הרצה

```bash
pnpm install
pnpm dev        # http://localhost:5291
pnpm build      # בדיקת טיפוסים + בילד
```

`App.vue` הוא דף הדגמה בלבד. הוא מדמה את הכותרת והרקע של האתר סביב הצ'אט.

## מבנה

```
src/data-verification/
  DataVerificationChat.vue   ← הקומפוננטה לשילוב באתר (מסך כניסה + צ'אט)
  index.ts                   ← מה שמייבאים
  script.ts                  ← התסריט: הנתונים, השלבים, הבדיקות והכרטיסים (TS נקי, בלי Vue)
  draft.ts                   ← טיוטת השיחה (יציאה וחזרה ממשיכות מאותה נקודה)
  styles.ts                  ← טוקנים של זכוכית וגרדיאנט
  icons.ts                   ← מיפוי אייקונים
  chat.css                   ← שתי אנימציות (כניסת הודעה, נקודות "מקליד")
  components/
    IntroScreen.vue          ← מסך הכניסה ("חדש", הסבר, "בואו נתחיל")
    ChatView.vue             ← מנוע השיחה + הממשק
    ChatMessage.vue          ← הודעה (העוזר על המסך, המשתמש בבועה)
    DataCard.vue / SummaryCard.vue
    SignaturePad.vue / TypingIndicator.vue / RichText.vue / BotMark.vue
  ui/                        ← כפתור, דיאלוג (מודאל / בוטום-שיט), פס התקדמות, עיגול אייקון
```

## שילוב באתר

1. מעתיקים את `src/data-verification/` לפרויקט.
2. תלויות: `vue` 3.5 ומעלה, `lucide-vue-next`, ו-Tailwind CSS v4.
3. מייבאים את `chat.css` פעם אחת, אחרי Tailwind. אם Tailwind לא סורק את התיקייה
   אוטומטית, מוסיפים `@source` שמצביע עליה.
4. הפונט הוא Noto Sans Hebrew, כמו בשאר האתר.

```vue
<script setup lang="ts">
import { DataVerificationChat, type RecruitData } from "@/data-verification";

const recruit: RecruitData = await api.getRecruitData(); // מהשרת

async function onComplete(data: RecruitData, signature: string) {
  await api.submitDataVerification({ data, signature });
  // לסמן את המשימה כ"בוצע"
}
</script>

<template>
  <!-- הקומפוננטה ממלאת את גובה העוטף: גובה המסך פחות הכותרת של האתר -->
  <div class="h-[calc(100dvh-64px)] md:h-[calc(100dvh-98px)]">
    <DataVerificationChat
      :recruit="recruit"
      @exit="router.push('/tasks')"
      @go-home="router.push('/')"
      @complete="onComplete"
    />
  </div>
</template>
```

| | שם | מה |
|---|---|---|
| prop | `recruit` | הנתונים הרשומים על המלש"ב (`RecruitData`). בלעדיו נטענים נתוני הדגמה (`DEMO_DATA`). |
| event | `exit` | יציאה מהמשימה, דרך פירורי הלחם, "יציאה" או "חזרה למשימות". |
| event | `go-home` | "לעמוד הבית" במסך הסיום. |
| event | `complete` | המלש"ב חתם. מקבל `(data: RecruitData, signature: string)`: הנתונים המאומתים, והחתימה כ-PNG ב-data URL. |

## איפה מתחברים לשרת

הכל מסומן בהערות בקוד:

- **נתוני פתיחה:** ה-prop `recruit`. השדה `RecruitData` ב-`script.ts` מתאר את המבנה.
- **מיקוד:** הפונקציה `lookupZip` ב-`script.ts` מחזירה כרגע ערך קבוע להדגמה.
  צריך להחליף אותה בקריאה לשירות המיקוד של דואר ישראל.
- **העלאת אסמכתא לבנק:** `onFile` ב-`ChatView.vue`. כרגע נשמר רק שם הקובץ.
- **שליחה:** האירוע `complete`.
- **טיוטה:** `draft.ts` שומר בזיכרון בלבד, ולכן היא מתאפסת ברענון. כל השדות בה
  הם JSON פשוט, כך שאפשר לשמור אותה ב-sessionStorage או בשרת.

## איך התסריט עובד

כל שלב ב-`STEPS` (`script.ts`) מגדיר:

- `enter`: אילו הודעות העוזר שולח. להודעה יכולים להיות `text`, `card`, ו-`ask`
  (שאלה שמוצגת אחרי הכרטיס).
- `options`: תשובות מהירות (צ'יפים).
- `text`: האם מותר להקליד, `placeholder`, ו-`validate` שמחזירה הודעת שגיאה או `null`.
- `special`: קלט מיוחד: `file`, `signature` או `done`.
- `answer(value, data)`: מחזירה את הנתונים המעודכנים, תגובה, ואת השלב הבא.

הסדר הוא: כתובת ותקשורת ← קרובים לשעת חירום ← חשבון בנק ← פטור זקן ←
סיכום וחתימה. בסיכום אפשר לבחור נושא לתיקון, ובסוף הנושא חוזרים ישר לסיכום.

טקסט חופשי מתורגם לתשובה כשזה אפשרי: "כן", "נכון" ו"בטח" נחשבים כן, ו"לא" ו"טעות"
נחשבים לא. כשהעוזר מצפה לבחירה מהצ'יפים ומקבל טקסט אחר, הוא עונה "לא בטוח שהבנתי".
**השיחה מתוסרטת ואין בה מודל שפה.**

## עיצוב

אותן מחלקות Tailwind כמו באתר: כחול המותג `#008ff0`, טקסט `#171c23`, כותרות
`#122736` וירוק `#69c600`.

- **העוזר** כותב ישירות על המסך. רק תשובות המשתמש מוצגות בבועה כחולה,
  עם פינה קטנה בימין למטה.
- **שדה ההקלדה והצ'יפים** בזכוכית (`GLASS`), כמו צ'יפי נתוני האיכות בעמוד
  הבית. הם צפים מעל השיחה.
- **כרטיסי הנתונים** בזכוכית אטומה יותר (`GLASS_PANEL`).
- **רקע העמוד:** הזכוכית צריכה את הגרדיאנט של האתר מאחוריה. בעמוד הזה בלי
  הטבעות הלבנות ובלי הכתם התחתון.
- **מובייל (מתחת ל-640px):** ההערה שמתחת לשדה ההקלדה מוסתרת. הדיאלוג נפתח
  כבוטום-שיט מתחת ל-768px.

## לשים לב

- **ניסוחים מגדריים:** הטקסטים בתסריט ניטרליים ("את/ה"). אבל שלבי הקרוב השני
  בנתוני ההדגמה כתובים בלשון נקבה ("הקרובה", "שלה", "גרה"), כי מדובר באם.
  במערכת האמיתית צריך לגזור את הניסוח מסוג הקרבה.
- **פטור זקן** נשאל את כולם.
